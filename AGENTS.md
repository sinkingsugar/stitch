# AGENTS.md

Working instructions for coding agents in this repository.

- Read [README.md](README.md) and [docs/design.md](docs/design.md) first. The design document is the source of truth for decisions and open questions; when a decision is taken or changes, update it in the same commit.
- Stitch depends on Otter (github.com/sinkingsugar/otter): the language its tools and agents are written in, successor of Shards 1.x, and its runtime. What Stitch needs from it is tracked there in `docs/host-requirements.md` (H1–H14 and its priorities). Do not name Stitch in the Otter repository: it calls Stitch "an agent-orchestrator host".
- Otter and engram (github.com/sinkingsugar/engram, with `tools/engram-fit`) are git dependencies pinned by `Cargo.lock`: a clean checkout builds with no sibling checkouts and no credentials, and every build that ships (CI, `just install`, the self-update) is `--locked`. To move a pin: `just bump-otter` / `just bump-engram` (the newest commit of its main), and commit `Cargo.lock`. For work across repositories, `just dev-link [otter] [engram]` builds this checkout against `../otter` and `../engram` (an untracked `.cargo/dev-link.toml` of `[patch]`es, included by `.cargo/config.toml`; `just quick` and `just check` warn while it is active, the build label says "(linked)", and `just install` and the self-update refuse to build); `just dev-unlink` puts `Cargo.lock`'s pins back exactly. Never commit `Cargo.lock` while linked (it loses its pins; CI's `--locked` fails). A cross-repo change lands in Otter or engram first, then the bump here.
- edge talk (`../edge-talk`) is the predecessor: reference it for features and lessons, do not port its architecture (see design §1).
- For a worktree, use `just worktree <name>` (at `../stitch-<name>`): its `target/` is a copy-on-write clone of the main checkout's (dependencies already built). llama.cpp (`stitch-llama`, a CUDA build of minutes) is built once per configuration in `~/.cache/stitch/llama` (`STITCH_LLAMA_CACHE`), shared by every checkout, so a new worktree links it in seconds. A worktree is not linked (`just dev-link` in it when it needs to be). When done, `just worktree-rm <name>` removes it with its build, and its branch once merged. Do not set a shared `CARGO_TARGET_DIR`: artifacts are named by their checkout's path, so a shared one only grows.
- While developing, `just quick`: fmt, and clippy and tests of the crates changed against main (committed or not), and the web client when `apps/client` changed. Never wait on a command for more than a few minutes without output: kill it.
- `just check` is the full Rust set: `cargo fmt -- --check` (not `--all`, which also reformats path dependencies such as a linked engram), `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`, and on macOS `just check-apple` (the crates an Apple client links, built for iOS and visionOS). CI (`.github/workflows/ci.yml`, on GitHub-hosted runners) runs the Linux set, `just client-check` and `just check-apple` (macOS) on every push and pull request; the CLA workflow (`.github/workflows/cla.yml`) asks a pull request's author to sign `.github/CLA.md`.
- Agents may push feature branches freely. Before pushing a change to main, `just quick` must pass (plus `just check-apple` when the change touches crates an Apple client links: `stitch-node`, `stitch-store`, `stitch-records`, `stitch-net`, `stitch-ffi`, …); CI checks Linux after the push.
- Everything here builds and tests from this checkout alone, with the documented commands. The iOS and visionOS app, the hosted vault service and Fragcolor's deployments are another repository, which builds against a checkout of this one; nothing here depends on it.
